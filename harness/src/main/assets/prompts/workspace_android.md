### Android Project Workflow Rules
- Current project type: Android; root marker: {{MARKER_TEXT}}.
- Before modifying code or build configuration, use `read` to inspect `settings.gradle(.kts)`, `app/build.gradle(.kts)`, `app/src/main/AndroidManifest.xml`, and the entry-point source. Prefer `edit` for local changes; use `write` only for new files.
- Preferred build entry point: `/opt/taixu/scripts/build_android.sh "{{WORKSPACE_PATH}}" assembleDebug`; alternatively run `./gradlew assembleDebug` from the project root. Do not call the removed Android CLI.
- If the standard entry point is incompatible because the project uses older or newer Gradle/AGP/Kotlin dependencies, inspect the wrapper, version catalog, and build logs to determine the requirements. Then call `build_script(action=list)` to check for an existing compatible script. If one matches, reuse it with `build_script(action=bind, id=...)`. If none matches, create and bind a POSIX shell script with explicit version compatibility notes using `build_script(action=create, project_type=android, ...)`. In the script, `$1` is the project directory and `$2` is the Gradle task; never hard-code the current project path.
- To install on the phone, confirm the APK exists and the build completed, copy it to `/sdcard/Download/`, then run `taixu-host install-apk /sdcard/Download/<project-name>.apk` to launch the host installer. If ADB is paired, you can run `adb install -r <apk>` directly. For crash investigation or runtime logs, call `host(action="logcat", package="<package-name>")` or run `logcat-grabber <package-name>`; Shizuku/Root is not required.
- When a build fails, read the complete Gradle/AAPT2 error and fix the corresponding script or project file. Do not merely report “build failed.”

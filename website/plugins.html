TAIXU PLUGIN GUIDE / SCHEMA 1

Bring your tools
装进TaiXu。

Use an online registry or a self-contained .txplugin，to bring commands, SDKs, scripts, and local services into the ARM64 Linux sandbox. This guide documents the actual constraints of the current importer and installer.

01 / Local and online plugins

SourceManifestAssets
Online pluginREMOTE + SCRIPTBuilt-in or signed registry
Local pluginLOCAL + LOCAL_PACKAGEImported by the user .txplugin

The importer forces local packages to be marked as source=LOCAL、offlineOnly=true、installMethod=LOCAL_PACKAGE。Local plugin与Online plugin使用The same ID 时，本地版本优先显示。

permissions 目前用于Manifest校验与Interface展示，不是安装脚本的权限沙箱。插件脚本仍能修改 PRoot 内当前用户可写的路径。

02 / 插件Package format

Local plugin使用 ZIP 容器，扩展名为 .txplugin。根Contents必须直接包含 manifest.json 和 payload/。

hello-arm64.txplugin
├── manifest.json
└── payload/
    ├── archives/       # SDK, NDK, Flutter, and other archives
    ├── scripts/        # Install, verification, and uninstall scripts
    ├── config/         # Configuration templates
    └── bin/            # ARM64 files
  • Only manifest.json 和 payload/，may be included; absolute paths and ..。
  • manifest.json maximum 1 MiB。
  • 解包条目累计maximum 8 GiB。
  • Before installation, the payload is copied to /opt/taixu/imports/<id>。

03 / Writing manifest.json

{
  "schemaVersion": 1,
  "id": "hello-arm64",
  "name": "Hello ARM64",
  "description": "TaiXu Local plugin示例",
  "version": "1.0.0",
  "publisher": "Your Name",
  "category": "DEVELOPER",
  "launchType": "command",
  "architectures": ["ARM64"],
  "permissions": [],
  "source": "LOCAL",
  "offlineOnly": true,
  "installMethod": "LOCAL_PACKAGE",
  "launchCommand": "hello",
  "verifyCommand": "hello",
  "commandLinks": ["hello"]
}
FieldCurrent constraints
idLowercase letters, digits, and hyphens; length 2–64.
versionMust not be empty; the standard format x.y.z。
launchTypeone_shot、command、pty、web 或 service。
architecturesmust include ARM64。
permissionsNETWORK、WORKSPACE_READ、WORKSPACE_WRITE、LOCAL_WEB。
commandLinksLinks by default to $TAIXU_TOOL_DIR/bin/<command>。

04 / Create a Hello plugin from scratch

Place the script at payload/bin/hello：

#!/bin/sh
echo "hello from TaiXu"

安装步骤必须创建工具Contents并恢复执行权限：

"installSteps": [
  "test -f \"$TAIXU_PLUGIN_PAYLOAD/bin/hello\"",
  "mkdir -p \"$TAIXU_TOOL_DIR/bin\"",
  "cp \"$TAIXU_PLUGIN_PAYLOAD/bin/hello\" \"$TAIXU_TOOL_DIR/bin/hello\"",
  "chmod 755 \"$TAIXU_TOOL_DIR/bin/hello\""
]

The installer provides TAIXU_TOOL_ID、TAIXU_TOOL_DIR、TAIXU_TOOL_DATA 和Local plugin专用的 TAIXU_PLUGIN_PAYLOAD。

05 / Packaging, versions, and quick updates

Windows PowerShell

Compress-Archive `
  -LiteralPath .\hello-arm64\manifest.json, .\hello-arm64\payload `
  -DestinationPath .\hello-arm64.zip -Force
Move-Item .\hello-arm64.zip .\hello-arm64.txplugin

Linux / macOS

cd hello-arm64
zip -r ../hello-arm64.txplugin manifest.json payload

Use a Zip64-capable tool for large plugins. For already-compressed .zip、.tar.gz 和 .deb 条目Prefer Store/NoCompression。

.txplugin 就是 ZIP。只更新Manifest或脚本时，可以复制旧包并替换少量 ZIP 条目，不必解压、重压缩所有大型归档；替换归档或改变压缩格式时才需要处理对应大文件。

  • The same id + version will be reported as already imported; it will not be unpacked or installed again.
  • The same ID 的不同版本当前会共存。
  • 当前版本Contents按字符串排序，并非完整 SemVer；修复前避免同时使用 1.0.9 与 1.0.10。
  • 确认新包后，Interface会连续执行导入与安装。

06 / Minimal RootFS 与大型依赖

Do not assume the system includes unzip、xz、file、readelf、jq、Python 或 Node。Prefer .tar.gz，and verify archives with SHA-256.

archive="$TAIXU_PLUGIN_PAYLOAD/archives/flutter-arm64.tar.gz"
test -s "$archive"
printf '%s  %s\n' "<SHA256>" "$archive" | sha256sum -c -
rm -rf /opt/flutter.staging
mkdir -p /opt/flutter.staging
tar -xzf "$archive" -C /opt/flutter.staging

Without relying on file/readelf 的 AArch64 检查：

elf_bytes() { od -An -t x1 "$@" 2>/dev/null | tr -d ' \n'; }
is_aarch64_elf() {
  test "$(elf_bytes -j 18 -N 2 "$1")" = "b700"
}
  • After extracting a ZIP, explicitly run chmod。
  • When finding tools that may be symlinks, use \( -type f -o -type l \)。
  • Do not pass a glob that may expand to multiple paths directly to test -x。
  • ARM64 架构The same不代表 Android/Bionic 与 Linux/glibc ABI 兼容。

07 / Live progress and install logs

Plugin scripts can emit monotonically increasing structured relative progress, which the app maps to the full installation progress bar:

[TAIXU_PROGRESS:47] [EXTRACT] Extracting Android NDK r29
[TAIXU_PROGRESS:75] [COMMAND] Configuring ADB
[TAIXU_PROGRESS:98] [VERIFY] Running final verification

Recommended labels are [COPY]、[EXTRACT]、[COMMAND]、[VERIFY] 标签。Do not enable set -x，because it may write tokens, proxy details, or environment variables to logs.

08 / Timeouts, storage, and rollback boundaries

  • Install scripts time out after 15 minutes by default; verification commands after 60 seconds.
  • 大包需要同时容纳私有插件副本、沙盒 payload 副本、staging 和最终Contents。
  • Framework transactions snapshot only /opt/taixu/tools/<id>。
  • /opt/android-sdk、/opt/flutter、/root/.gradle and other global paths must be staged and cleaned up by the plugin itself.
  • 日志出现 ROLLED_BACK does not mean every global file has been restored.
  • verifyCommand must return 0; do not rely on legacy compatibility command fallbacks.

09 / Pre-release checklist

  • ZIP 根Contents、1 MiB manifest 和 8 GiB 解包限制均满足。
  • 本地/在线Source、ID、版本、ARM64、启动类型与权限Field正确。
  • Every large file has a pinned SHA-256.
  • Without relying on未声明的 unzip、xz、file、readelf 等可选命令。
  • ELF files, symlinks, and ZIP executable bits are handled.
  • Import, install, validation, and launch work offline.
  • Fresh install, duplicate import, upgrade, and uninstall are all tested.
  • Structured progress is monotonic, and logs contain no sensitive information.
  • Staging can be cleaned after failure, and all disk copies have been accounted for.

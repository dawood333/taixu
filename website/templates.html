TAIXU PROJECT TEMPLATE GUIDE / SCHEMA 1

Turn a project
into a shareable starting point.

A single ZIP can contain a project scaffold, dynamic fields, a standard square preview, and generation hooks that require explicit user approval. This guide documents the actual constraints of the current template importer, form renderer, and materialization engine.

01 / From project to template

  1. Create a template directory and add the project scaffold.
  2. Declare the type, category, preview image, and variables in template.json.
  3. Write replaceable values as {{variableName}}.
  4. Optional: include pre- or post-generation scripts in template-hooks/.
  5. Compress the directory into a ZIP and import it via Workshop → Template Manager.
  6. After validation, export the ZIP and share it with other users.

The quickest way to start is to export a built-in template from Template Manager. Change the id in template.json and remove the reserved builtin. prefix before importing it.

02 / Template package directory structure

Templates use a standard ZIP. The manifest can sit at the ZIP root, or the ZIP can contain a single template folder.

my-android-template/
├── template.json
├── preview.png                   # optional, fixed at 270×270
├── template-hooks/             # optional
│   ├── before-create.sh
│   └── after-create.sh
└── app/
    ├── build.gradle.kts
    └── src/main/java/TAIXU_PACKAGE_PATH/
        └── MainActivity.kt.template
  • At most 5,000 ZIP entries.
  • Maximum single-file size: 16 MiB.
  • Maximum total uncompressed size: 128 MiB.
  • Absolute paths, Windows drive letters, and paths containing .. that escape the destination are rejected.

03 / Writing template.json

{
  "schemaVersion": 1,
  "id": "example.android-basic",
  "name": "Basic Android",
  "version": "1.0.0",
  "description": "A reusable Android starter",
  "projectType": "ANDROID",
  "category": {
    "id": "starter",
    "name": "Starter",
    "sortOrder": 0
  },
  "previewImage": "preview.png",
  "variables": []
}
FieldCurrent constraints
schemaVersionCurrently fixed at 1.
idLowercase letters and digits, optionally separated by dots, underscores, or hyphens; builtin. is a reserved prefix.
projectTypeANDROID, FLUTTER, or GENERAL.
categoryGroup shown in the template picker; lower sortOrder values appear first.
previewImageOptional single 1:1 preview image, 270×270.
variablesDeclares the dynamic form and all template variables.
hooksOptional pre- and post-generation hooks.
validationRules for validating generated output.

The manifest is parsed strictly; unknown fields are not ignored. The machine-readable JSON Schema is available in the repository.

04 / Render dynamic UI from the manifest

"variables": [
  {
    "name": "packageName",
    "label": "Package name",
    "prompt": true,
    "inputType": "TEXT",
    "placeholder": "com.example.app",
    "validationRegex": "^[a-zA-Z_][\\w]*(\\.[a-zA-Z_][\\w]*)+$"
  },
  {
    "name": "uiStyle",
    "label": "UI style",
    "prompt": true,
    "inputType": "SELECT",
    "defaultValue": "compose",
    "options": [
      { "value": "compose", "label": "Jetpack Compose" },
      { "value": "views", "label": "Android Views" }
    ]
  }
]

prompt: true automatically renders controls in the final project-creation step. Supported types: TEXT, MULTILINE, NUMBER, BOOLEAN, SELECT, and SECRET.

  • Variable names must match ^[A-Za-z][A-Za-z0-9_]*$ and must be unique.
  • Hidden required variables need default values, except for system-derived variables.
  • SELECT must have unique options; optional fields may be left blank.
  • Workshop supplies the project name and creation path; do not model them as dynamic fields.

The system provides projectName, appName, and projectPath. If the template declares appName as a dynamic field, the user input takes precedence. Java package-name rules are enabled only if the template declares packageName or packagePath.

A template can declare projectName as a fixed variable with prompt: false and use validationRegex to constrain the shared project-name field. On validation failure, Workshop displays the variable’s description and blocks creation rather than silently rewriting the user’s input.

05 / Replacing file contents and paths

Variables can be used in both text content and relative paths:

modules/{{moduleName}}/config.json.template

{
  "name": "{{projectName}}",
  "mode": "{{buildMode}}"
}

Variables are replaced during generation, and the trailing .templateis removed. Use this suffix for any text file requiring substitutions;Java、Kotlin、Dart、JSON、YAML、TOML、Shell、Python、JavaScript、C/C++ and other common text formats are detected automatically.

The package directory uses TAIXU_PACKAGE_PATH, which is replaced during creation with the directory hierarchy corresponding to the package name. Do not use placeholder directories starting with underscores, as Android AAPT may ignore them. Generated paths are normalized again and escaping paths are rejected. If an undeclared {{unknownVariable}} remains in a file, creation fails.

06 / Standard square preview image

A template declares only one preview image, with no separate variants for phones, tablets, portrait, or landscape. The aspect ratio is fixed at 1:1, and the dimensions must be 270×270 px. PNG, JPEG, WebP, and GIF are supported; each image must be at most 4 MiB.

Keep the logo, title, and key content within the central safe area and leave about 8% padding around the edges so cards remain clear at different sizes.

07 / Include auditable generation hooks

"hooks": {
  "beforeCreate": "template-hooks/before-create.sh",
  "afterCreate": "template-hooks/after-create.sh"
}

Hooks do not run during import, preview, or export. When creating a project, TaiXu displays the script contents and runs them only after the user explicitly grants permission.

  • Hooks must be located in template-hooks/, with a maximum size of 1 MiB each.
  • They run in the new project directory inside the Linux sandbox; each stage has a 60-second limit.
  • beforeCreate runs before template files are copied, and afterCreate runs after materialization.
  • The project path is TAIXU_PROJECT_DIR.
  • Variables are passed as TAIXU_VAR_<UPPERCASE_VARIABLE_NAME>.
  • A nonzero exit aborts creation and returns error output to the UI.
#!/bin/sh
set -eu
mkdir -p generated
printf '%s\n' "$TAIXU_VAR_PROJECTNAME" > generated/project-name.txt

08 / Template-provided output validation

"validation": {
  "requiredFiles": ["app/src/main/java/TAIXU_PACKAGE_PATH/MainHook.kt"],
  "forbiddenFiles": ["app/src/main/java/TAIXU_PACKAGE_PATH/LegacyHook.kt"],
  "contentRules": [
    {
      "path": "app/src/main/assets/xposed_init",
      "equals": "{{packageName}}.MainHook"
    }
  ]
}

requiredFiles declares required files, forbiddenFiles declares forbidden outputs, and contentRules supports equals, contains, and excludes. Both paths and content can use template variables.

Validation runs after afterCreate finishes. Rules belong to the template itself, not its built-in ID, and remain consistent after renaming, exporting, and re-importing.

09 / Package, import, and share

Windows PowerShell

Compress-Archive `
  -Path .\my-android-template\* `
  -DestinationPath .\my-android-template.zip -Force

Linux / macOS

cd my-android-template
zip -r ../my-android-template.zip .

In the Android app, open Workshop → More → Template Manager → Import ZIP. After import, the template appears under the matching project type and category; no app-code or registry changes are required.

You can also export templates from Template Manager. User templates can be deleted; built-in templates are protected.

10 / A complete template without a package name

GENERAL templates do not depend on Android package names:

{
  "schemaVersion": 1,
  "id": "example.shell-project",
  "name": "Shell Project",
  "version": "1.0.0",
  "projectType": "GENERAL",
  "category": { "id": "script", "name": "Scripts", "sortOrder": 0 },
  "variables": [
    {
      "name": "greeting",
      "label": "Greeting",
      "prompt": true,
      "inputType": "TEXT",
      "defaultValue": "Hello"
    }
  ]
}

In README.md.template, writing # {{projectName}}\n{{greeting}} is enough. The shared creation screen still supplies the project name and path.

11 / Pre-release checklist

  • The manifest passes the v1 JSON Schema and contains no unknown fields.
  • The ID does not use builtin.; variable names and category IDs are valid and unique.
  • Project name and path are not declared as dynamic fields.
  • All text placeholders are declared, and path variables cannot escape the target directory.
  • The single preview image meets the 1:1, 270×270, format, and size requirements.
  • Hooks are in the designated directory, contain no secrets, and finish within 60 seconds.
  • Complete import, form entry, creation, export, and re-import in a fresh directory.
  • Confirm GENERAL templates are not incorrectly prompted for a Java package name.
